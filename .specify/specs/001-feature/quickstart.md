# 변경 검증 워크스루 — 신규 메뉴 추가(R1-B)

## 목적

이 절차는 네 관리 화면에서 저장 후 재조회가 보이고, 메뉴·코드 사용여부 및 기간으로 차단되는 요청이 서버에서 무변경으로 거부되는지 확인한다. 검증은 기존 Docker Compose 환경과 인증된 R09 세션에서 수행한다.

## 사전 조건

1. `backend`, `frontend`, `database` 서비스가 정상 상태여야 한다.
2. `GET /api/health`가 `success: true`를 반환해야 한다.
3. R09 권한이 있는 기존 관리자 계정으로 로그인하고 브라우저 세션을 유지한다.
4. 저장 대상은 각 목록 응답에서 조회한 실제 `menuId`, `groupId`, `codeValue`, `settingKey`, `targetYear`를 사용한다. UI 또는 API에 예시 식별자를 고정하지 않는다.

## 공통 확인 방법

1. 해당 화면에서 저장을 선택하면 표시되는 확인 메시지에서 확인한다.
2. 성공 안내가 표시된 뒤 같은 화면의 조회 동작으로 다시 읽는다.
3. 재조회 결과가 저장한 값과 같음을 확인한다.
4. 필수값, 닫힌 값 집합, 기간 또는 유일성 위반 요청은 `ApiError`로 거부되고 재조회 결과가 저장 전과 같은지 확인한다.

## 1. 메뉴 사용 관리

경로: `시스템 관리 > 메뉴 관리 > 메뉴 사용 관리` (`/system/menus/usage`)

1. 메뉴 사용 설정을 조회하고 실제 메뉴를 선택한다.
2. `useYn`, 필수 `exposureStartAt`, 선택 `exposureEndAt`를 저장한다.
3. 성공 안내 뒤 같은 메뉴를 재조회해 사용여부와 노출 시작·종료일시가 유지되는지 확인한다.
4. 시작일시보다 이른 종료일시 또는 누락된 시작일시 저장은 400 `ApiError`이며 기존 설정이 바뀌지 않는지 확인한다.
5. 중지되었거나 서버 시각 기준 노출기간 밖인 메뉴는 사용자 메뉴에서 사라지고, 해당 메뉴의 direct route/API 요청도 403으로 차단되는지 확인한다.

## 2. 코드 사용 관리

경로: `시스템 관리 > 공통코드 관리 > 코드 사용 관리` (`/system/common-codes/usage`)

1. 코드 사용 설정을 조회하고 실제 `groupId`와 `codeValue`를 선택한다.
2. `useYn`, 필수 `effectiveStartDate`, 선택 `effectiveEndDate`를 저장한다.
3. 성공 안내 뒤 같은 코드 조합을 재조회해 사용여부와 적용기간이 유지되는지 확인한다.
4. 시작일보다 이른 종료일 또는 누락된 시작일 저장은 400 `ApiError`이며 기존 설정이 바뀌지 않는지 확인한다.
5. 종료 또는 미사용 코드는 신규 입력 선택값에서 제외되지만, 과거 기록 조회에서는 기존 `codeValue`와 코드명이 유지되는지 확인한다.
6. 종료된 코드는 `useYn`을 사용으로 바꾸고 종료일을 연장해 되돌릴 수 있으며, 동일한 기간 규칙이 적용되는지 확인한다.

## 3. 공통 환경설정

경로: `시스템 관리 > 시스템 환경설정 > 공통 환경설정` (`/system/settings/common-environment`)

1. 공통 환경설정을 조회하고 실제 설정 항목을 선택한다.
2. `settingKey`와 `settingValue`를 저장하고 성공 안내 뒤 재조회한다.
3. 선택한 항목만 갱신되고 다른 항목은 유지되는지 확인한다.
4. 페이지당 조회건수는 `20`, `50`, `100`만 저장할 수 있으며, 목록 진입 기본값이 바뀌어도 사용자가 세 값 중 다른 값을 선택할 수 있는지 확인한다.
5. 세션 유휴시간 변경은 새로 생성되는 세션에만 적용되고 이미 열린 세션은 변경되지 않는다는 화면 안내가 표시되는지 확인한다.

## 4. 기준연도 관리

경로: `시스템 관리 > 시스템 환경설정 > 기준연도 관리` (`/system/settings/reference-years`)

1. 기준연도 설정을 조회하고 실제 대상 연도를 선택한다.
2. `currentEvaluationYear`, `defaultQueryYear`, `targetYear`, `baselineCopyYn`, `initializationYn`를 저장한다.
3. 성공 안내 뒤 재조회해 현재 평가연도, 기본 조회연도, 대상 연도별 선택값이 유지되는지 확인한다.
4. 유효한 현재 평가연도 또는 기본 조회연도 설정을 중복 저장하면 400 `ApiError`와 무변경으로 거부되는지 확인한다.
5. 기본 조회연도는 사용자 화면의 초기값으로 제공되지만 다른 연도를 조회할 수 있는지 확인한다.
6. 복사·초기화 여부 저장은 설정값만 바꾸며 기존 연도 자료를 변경하거나 실제 복사·초기화 작업을 실행하지 않는지 확인한다.

## 차단 결과

차단 여부는 화면 숨김만으로 판정하지 않는다. 세션이 없으면 401, 권한이 없거나 메뉴가 중지·기간 밖이면 403, 입력·기간·유일성 위반이면 400 `ApiError`를 확인한다. 모든 차단 요청은 저장·처리 결과를 변경하지 않아야 하므로 대응 목록을 재조회해 저장 전 값이 보존되는지 확인한다.
